    Guía de comandos · UT4 · Implantación de CMS¶

    Esta guía reúne los comandos más útiles para trabajar la implantación de WordPress con Docker Compose en esta unidad.

    Importante: no hace falta memorizarlo todo. Lo importante es entender qué hace cada comando y cuándo conviene usarlo.

    1. Antes de arrancar¶

    Sitúate dentro de la carpeta donde está el fichero docker-compose.yml:

    cd ut4-wordpress

    Para comprobar que Docker Compose está disponible:

    docker compose version

    2. Arranque de la pila¶

    Levantar servicios en segundo plano:

    docker compose up -d

    Levantar servicios viendo logs en primer plano:

    docker compose up

    Reconstruir y arrancar:

    docker compose up -d --build

    3. Ver el estado¶

    Ver servicios levantados:

    docker compose ps

    Ver todos los contenedores de Docker:

    docker ps

    Ver configuración expandida del Compose:

    docker compose config

    4. Logs y diagnóstico¶

    Ver logs de todos los servicios:

    docker compose logs

    Seguir los logs en tiempo real:

    docker compose logs -f

    Ver solo los logs de WordPress:

    docker compose logs -f wordpress

    Ver solo los logs de la base de datos:

    docker compose logs -f db

    5. Parar, reiniciar y destruir¶

    Parar servicios sin borrar nada:

    docker compose stop

    Reiniciar servicios:

    docker compose restart

    Bajar la pila conservando volúmenes:

    docker compose down

    Bajar la pila borrando también los volúmenes:

    docker compose down -v

    Atención: down -v suele implicar perder el estado del CMS si la persistencia está en esos volúmenes.

    6. Entrar dentro de los contenedores¶

    Abrir shell en el contenedor WordPress:

    docker compose exec wordpress bash

    Abrir shell en la base de datos:

    docker compose exec db bash

    Si la imagen no tiene bash, prueba con:

    docker compose exec wordpress sh

    7. Comprobar conectividad básica¶

    Comprobar si el servicio WordPress responde desde el host:

    curl -I http://localhost:8080

    Ver si un puerto local está escuchando:

    ss -tulpn

    o, según sistema:

    netstat -tulpn

    8. Trabajar con la base de datos¶

    Entrar al cliente MariaDB/MySQL dentro del contenedor:

    docker compose exec db mariadb -u root -p

    o bien:

    docker compose exec db mysql -u root -p

    Conectar directamente a la base WordPress con usuario de aplicación:

    docker compose exec db mariadb -u wordpress -p wordpress

    9. Exportar una copia rápida de la base de datos¶

    Ejemplo orientativo:

    docker compose exec db sh -c 'mariadb-dump -u root -p"$MARIADB_ROOT_PASSWORD" "$MARIADB_DATABASE"' > backup.sql

    El nombre exacto del comando puede variar según imagen (mysqldump o mariadb-dump).

    10. Inspección de volúmenes¶

    Listar volúmenes:

    docker volume ls

    Inspeccionar uno en concreto:

    docker volume inspect ut4_wordpress_wp_data

    11. Abrir el sitio y el panel¶

    Frontend:

    http://localhost:8080

    Panel de administración:

    http://localhost:8080/wp-admin

    Si has publicado el puerto en otra cifra, sustituye 8080 por la que corresponda.

    12. Comandos muy útiles para la práctica¶

    Caso 1. “No me abre el sitio”¶

    docker compose ps
docker compose logs -f wordpress
docker compose logs -f db

    Caso 2. “Creo que he borrado el estado”¶

    docker volume ls
docker compose down
docker compose up -d

    Caso 3. “Quiero reiniciar limpio”¶

    docker compose down -v
docker compose up -d

    Caso 4. “Quiero comprobar que persiste”¶

    1. crea una página o cambia el título del sitio;
    2. ejecuta:
    docker compose restart
    1. vuelve a entrar y comprueba si sigue ahí.

    13. Errores típicos de comandos¶

    Error: usar localhost como host de base de datos dentro del contenedor¶

    En Compose, WordPress debe conectar con el servicio db, no con localhost.

    Error: no estar en la carpeta del Compose¶

    Si Docker no encuentra el fichero, revisa el directorio actual.

    Error: borrar volúmenes sin querer¶

    docker compose down -v es útil, pero destructivo para el estado del sitio.

    Error: pensar que restart y down -v hacen lo mismo¶

    No.
    restart reinicia servicios.
    down -v destruye contenedores y volúmenes definidos.

    14. Recordatorio final¶

    Para esta UT, los cuatro comandos estrella son:

    docker compose up -d
docker compose ps
docker compose logs -f
docker compose down

    Si además entiendes bien volúmenes, puertos y nombres de servicio, ya tienes una base muy sólida.
