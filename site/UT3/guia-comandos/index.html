    Guía de comandos de la UT3¶

    Esta guía no sustituye a los apuntes. Sirve como chuleta operativa para trabajar más deprisa en el entorno de la UT.

    0. Comprobar que PHP está disponible¶

    Qué hace¶

    Permite comprobar que PHP está instalado y accesible desde terminal.

    Para qué sirve en esta UT¶

    Sin PHP no podrás probar los scripts que conectan con la base de datos.

    Qué debes observar¶

    php -v

    Debe devolverte la versión instalada.

    1. Comprobar que PHP tiene PDO y drivers disponibles¶

    Qué hace¶

    Permite verificar si PHP tiene soporte para PDO y qué motores están disponibles.

    Cuándo usarlo¶

    Cuando una conexión falla o cuando quieres confirmar si están activos pdo_sqlite o pdo_mysql.

    Desde sistema local¶

    php -m | grep -i pdo
php -m | grep -i sqlite
php -m | grep -i mysql

    También puedes usar este script rápido:

    <?php
print_r(PDO::getAvailableDrivers());

    Si trabajas con Docker¶

    docker compose exec php php -m | grep -i pdo
docker compose exec php php -m | grep -i sqlite
docker compose exec php php -m | grep -i mysql

    2. Levantar el entorno¶

    Con servidor embebido de PHP¶

    Lanza un servidor local sencillo para pruebas cuando quieres probar rápido la práctica con SQLite o una aplicación pequeña.

    Ejecútalo desde la carpeta adecuada, normalmente public/ o la raíz del proyecto según tu estructura.

    php -S localhost:8000 -t public

    Con Docker Compose¶

    docker compose up -d
docker compose ps
docker compose logs -f php
docker compose logs -f db

    3. Trabajar con SQLite¶

    Abrir la base de datos desde terminal¶

    sqlite3 data/agenda.sqlite

    Comandos básicos dentro de sqlite3¶

    .tables
.schema contactos
SELECT * FROM contactos;
.quit

    Borrar la base de datos SQLite y regenerarla¶

    rm -f data/agenda.sqlite

    Úsalo solo si sabes que tu aplicación la recrea o si estás reiniciando una práctica.

    4. Trabajar con MariaDB / MySQL desde terminal¶

    Conectar al contenedor o servicio¶

    mysql -h 127.0.0.1 -P 3306 -u agenda_user -p agenda

    Si el servicio se llama db dentro de Docker¶

    docker compose exec db mariadb -u root -p

    o, según imagen:

    docker compose exec db mysql -u root -p

    Comandos SQL frecuentes¶

    SHOW DATABASES;
USE agenda;
SHOW TABLES;
DESCRIBE contactos;
SELECT * FROM contactos;

    5. Crear base de datos y usuario de aplicación en MySQL/MariaDB¶

    Para qué sirve¶

    Evita trabajar con root en la aplicación.

    Recomendación¶

    Hazlo una vez y reutilízalo en la práctica 2.

    Hazlo como administrador del gestor, no como usuario normal de la aplicación.

    CREATE DATABASE agenda CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER 'agenda_user'@'%' IDENTIFIED BY 'agenda_pass';

GRANT ALL PRIVILEGES ON agenda.* TO 'agenda_user'@'%';

FLUSH PRIVILEGES;

    Recomendación didáctica¶

    En una práctica de aula puedes conceder todos los privilegios para simplificar inicialización.
    En un entorno más profesional conviene separar mejor los permisos. CREATE y ALTER no son necesarios para el CRUD básico.

    6. Probar la conexión PDO rápidamente¶

    SQLite¶

    <?php
try {
    $pdo = new PDO('sqlite:data/agenda.sqlite');
    echo 'Conexión SQLite OK';
} catch (PDOException $e) {
    echo 'Error SQLite: ' . $e->getMessage();
}

    MySQL¶

    <?php
try {
    $pdo = new PDO(
        'mysql:host=db;port=3306;dbname=agenda;charset=utf8mb4',
        'agenda_user',
        'agenda_pass'
    );
    echo 'Conexión MySQL OK';
} catch (PDOException $e) {
    echo 'Error MySQL: ' . $e->getMessage();
}

    7. Crear tabla desde PHP con exec()¶

    Qué hace¶

    Ejecuta sentencias SQL que no devuelven filas.

    <?php
$sql = "
    CREATE TABLE IF NOT EXISTS contactos (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        nombre TEXT NOT NULL,
        email TEXT NOT NULL
    )
";

$pdo->exec($sql);

    8. Insertar con prepare() y execute()¶

    Qué hace¶

    Permite usar consultas preparadas con parámetros.

    <?php
$stmt = $pdo->prepare("
    INSERT INTO contactos (nombre, email)
    VALUES (:nombre, :email)
");

$stmt->execute([
    ':nombre' => 'Ana',
    ':email' => 'ana@ejemplo.com',
]);

    9. Leer resultados¶

    Qué hace¶

    Recupera filas desde la base de datos.

    <?php
$stmt = $pdo->query("SELECT * FROM contactos ORDER BY id DESC");
$filas = $stmt->fetchAll();
print_r($filas);

    10. Consultar una fila concreta¶

    Qué hace¶

    Permite recuperar un solo registro por identificador.

    <?php
$stmt = $pdo->prepare("SELECT * FROM contactos WHERE id = :id");
$stmt->execute([':id' => 1]);
$fila = $stmt->fetch();

    11. Actualizar un registro¶

    Qué hace¶

    Modifica una fila existente.

    <?php
$stmt = $pdo->prepare("
    UPDATE contactos
    SET nombre = :nombre, email = :email
    WHERE id = :id
");

$stmt->execute([
    ':nombre' => 'Ana Pérez',
    ':email' => 'ana.perez@ejemplo.com',
    ':id' => 1,
]);

    12. Borrar un registro¶

    Qué hace¶

    Elimina una fila por identificador.

    <?php
$stmt = $pdo->prepare("DELETE FROM contactos WHERE id = :id");
$stmt->execute([':id' => 1]);

    13. Verificar errores frecuentes¶

    Checklist rápido¶

    1. ¿PHP está disponible?
2. ¿PDO está activo?
3. ¿Está el driver correcto?
4. ¿El DSN apunta al sitio correcto?
5. ¿La tabla existe?
6. ¿El usuario tiene permisos?
7. ¿Estoy usando prepare() con datos variables?
8. ¿Estoy mostrando o capturando el error en desarrollo?

    Errores habituales¶

    • could not find driver
    • no such table
    • access denied
    • unknown database

    Driver no encontrado¶

    php -m | grep -i pdo
php -m | grep -i sqlite
php -m | grep -i mysql

    Tabla no existente¶

    Comprueba:

    SHOW TABLES;

    o en SQLite:

    .tables

    Ruta SQLite incorrecta¶

    Comprueba:

    ls -la data

    Variables de conexión mal configuradas¶

    Revisa:

    • host
    • puerto
    • nombre de base de datos
    • usuario
    • contraseña
    • charset=utf8mb4

    14. Revisar registros desde Adminer / phpMyAdmin como apoyo visual¶

    Qué conviene mirar ahí¶

    • si la tabla se ha creado;
    • si realmente se han insertado datos;
    • si un UPDATE ha cambiado lo esperado;
    • si la estructura coincide con tu SQL.

    Qué no debes hacer siempre desde ahí¶

    • crear manualmente toda la práctica y luego decir que la ha hecho el PHP;
    • depender de clics que no sabes reproducir por código.

    15. Comandos rápidos de depuración en Docker¶

    docker compose ps
docker compose logs -f php
docker compose logs -f db
docker compose exec php php -v
docker compose exec php php -m
docker compose exec php ls -la /var/www/html

    16. Checklist express antes de entregar una práctica¶

    • El proyecto arranca sin error fatal
    • PDO y el driver correspondiente están disponibles
    • La conexión está centralizada
    • La tabla existe
    • El alta funciona
    • El listado funciona
    • La edición funciona
    • El borrado funciona
    • Se usan consultas preparadas
    • La salida HTML está escapada
    • No se usa root como usuario de la app en MySQL
