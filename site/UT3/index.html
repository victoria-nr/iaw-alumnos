    UT3. PHP con acceso a bases de datos¶

    Presentación de la unidad¶

    En la UT2 trabajaste con PHP como lenguaje de servidor para generar páginas, procesar formularios y organizar lógica básica. En esta UT damos el paso natural en cualquier aplicación web real: persistir información en una base de datos y recuperarla de forma segura.

    A partir de aquí PHP deja de ser solo un lenguaje que “pinta HTML” y pasa a convertirse en el intermediario entre:

    • el navegador del usuario;
    • la lógica de la aplicación;
    • y el sistema gestor de bases de datos.

    El foco de la unidad no es aprender SQL de forma aislada, sino usar SQL desde PHP con sentido profesional. Por eso la pieza central será PDO, que nos permitirá trabajar con SQLite y MariaDB/MySQL usando una misma forma de programar.

    Idea-fuerza de la UT

    Una aplicación web útil casi siempre necesita recordar algo: usuarios, productos, incidencias, reservas, mensajes o configuraciones. Esa memoria vive en una base de datos, y PHP necesita una forma robusta de hablar con ella.

    Resultado de aprendizaje trabajado¶

    RA6. Genera documentos web con acceso a bases de datos utilizando lenguajes de guiones de servidor.

    Criterios de evaluación del RA6¶

    1. Se han identificado los sistemas gestores de bases de datos más utilizados en entornos web.
    2. Se ha verificado la integración de los sistemas gestores de bases de datos con el lenguaje de guiones de servidor.
    3. Se ha configurado en el lenguaje de guiones la conexión para el acceso al sistema gestor de base de datos.
    4. Se han creado bases de datos y tablas en el gestor utilizando el lenguaje de guiones.
    5. Se ha obtenido y actualizado la información almacenada en bases de datos.
    6. Se han aplicado criterios de seguridad en el acceso de los usuarios.
    7. Se ha verificado el funcionamiento y el rendimiento del sistema.

    Objetivo didáctico general¶

    Que el alumnado sea capaz de construir una pequeña aplicación web en PHP conectada a una base de datos relacional y realizar sobre ella operaciones CRUD básicas de forma segura, estructurada y verificable.

    Qué vas a aprender realmente¶

    Al terminar esta UT deberías poder:

    • explicar qué papel cumple una base de datos en una aplicación web;
    • distinguir entre SQLite y MariaDB/MySQL en un contexto web;
    • conectar PHP con un SGBD usando PDO;
    • crear tablas y datos iniciales desde PHP;
    • realizar altas, consultas, modificaciones y borrados;
    • validar datos en servidor;
    • usar consultas preparadas para evitar errores y riesgos de seguridad;
    • entender por qué una aplicación no debe conectarse como root;
    • comprobar si una aplicación con base de datos funciona bien y dónde mirar cuando falla.

    Enfoque didáctico de la UT¶

    Esta unidad se ha diseñado con una progresión muy deliberada:

    1. Primero SQLite, porque elimina fricción inicial:
    2. no requiere servidor separado;
    3. la base de datos es un fichero;

    4. permite concentrarse en PDO y en el flujo CRUD.

    5. Después MariaDB/MySQL, porque representa mejor un escenario profesional:

    6. cliente y servidor separados;
    7. gestión de usuarios y permisos;
    8. herramientas visuales como phpMyAdmin o Adminer;

    9. despliegues más cercanos a entornos reales.

    10. Siempre desde PHP, no desde una teoría abstracta de bases de datos:

    11. el SQL aparece cuando hace falta;
    12. cada consulta tiene un propósito funcional;
    13. cada decisión técnica se conecta con una necesidad de la aplicación.

    Relación con otras UT¶

    • Vienes de la UT1: reutilizas el entorno reproducible de trabajo.
    • Continúas la UT2: el código PHP ya no se queda “en memoria”, ahora persiste datos.
    • Prepara la UT4 y la UT5: muchos CMS y aplicaciones web usan exactamente esta lógica por debajo.

    Secuenciación orientativa (12 horas)¶

    Bloque Horas aprox. Idea principal
    1 2 h Qué problema resuelve una base de datos en una app web
    2 2 h SGBD habituales y por qué usamos SQLite y MariaDB/MySQL
    3 2 h PDO: conexión, DSN, errores, lectura de resultados
    4 2 h CRUD completo con SQLite
    5 2 h Migración del mismo patrón a MariaDB/MySQL
    6 1 h Seguridad básica, validación, usuarios y permisos
    7 1 h Comprobación, rendimiento básico y cierre de la UT

    C --> E[MariaDB / MySQL]

    E --> B

    U->>N: Envía formulario
    N->>S: Petición HTTP

    P-->>S: Genera HTML
    S-->>N: Respuesta HTTP
    N-->>U: Ve datos actualizados

    Conclusión importante¶

    • PHP procesa la petición.
    • La base de datos conserva y organiza la información.
    • PDO permite hablar con distintos motores siguiendo un patrón parecido.

    Herramientas que usaremos¶

    • PHP
    • PDO
    • SQLite
    • MariaDB/MySQL
    • consultas preparadas
    • Adminer o phpMyAdmin como apoyo visual
    • VS Code
    • entorno reproducible de la UT1

    Qué no vamos a hacer todavía¶

    En esta unidad todavía no vamos a:

    • diseñar una base de datos compleja con muchas relaciones;
    • optimizar como en un entorno de producción real;
    • entrar en ORMs o frameworks;
    • estudiar administración avanzada del SGBD;
    • convertir esto en una API.

    La prioridad aquí es construir una base sólida y transferible.

    Qué serás capaz de construir al final¶

    Al terminar la unidad podrás desarrollar una miniaplicación PHP con:

    • una conexión reutilizable a base de datos;
    • creación de tablas desde código;
    • formularios que guardan datos;
    • listados que leen datos persistentes;
    • edición y borrado;
    • validación en servidor;
    • consultas preparadas;
    • cambio razonado entre SQLite y MariaDB/MySQL.

    Productos de trabajo de la unidad¶

    Práctica 1¶

    Una agenda básica con SQLite + PDO y operaciones CRUD completas.

    Práctica 2¶

    Un mini gestor con MariaDB/MySQL + PDO reutilizando la lógica de la práctica 1 y añadiendo filtro funcional.

    Errores típicos que vamos a combatir¶

    • pensar que PDO “es la base de datos”;
    • concatenar datos del usuario dentro del SQL;
    • creer que required en HTML ya sustituye la validación del servidor;
    • usar root como usuario de aplicación;
    • mostrar errores técnicos sin control al usuario final;
    • olvidar escapar la salida con htmlspecialchars();
    • no comprobar si el driver PDO está disponible;
    • creer que SQLite y MySQL obligan a rehacer toda la aplicación.

    Cómo se evaluará¶

    La evaluación combinará:

    • prácticas;
    • cuestionario;
    • validación técnica rápida;
    • comprobación de comprensión real y transferencia.

    Se valorará especialmente que el alumnado:

    • entienda la relación entre PHP y el SGBD;
    • configure correctamente la conexión;
    • use consultas preparadas y validación;
    • explique qué cambia y qué no cambia al pasar de SQLite a MySQL;
    • demuestre que sabe corregir errores típicos.

    Criterio metodológico importante¶

    En esta UT se acepta el uso de IA como apoyo, pero no sustituye la comprensión.
    Por eso la validación está pensada para comprobar que el alumno sabe:

    • explicar qué hace su código;
    • adaptar una consulta;
    • localizar un error de conexión;
    • justificar por qué usa prepare() y no concatenación;
    • cambiar de SQLite a MySQL ajustando el DSN y el entorno.

    Recomendación de estudio¶

    No intentes memorizar todas las consultas SQL. Lo importante es entender este ciclo:

    1. recibo datos;
    2. valido datos;
    3. preparo consulta;
    4. ejecuto consulta;
    5. trato resultado;
    6. muestro salida escapada;
    7. verifico que todo funciona.

    Ese ciclo aparece una y otra vez en aplicaciones web reales.

    Antes de empezar¶

    Conviene tener claros estos conceptos de la UT2:

    • variables y arrays en PHP;
    • formularios GET y POST;
    • separación básica entre HTML y lógica;
    • inclusión de ficheros;
    • tratamiento básico de errores.

    Si algo de eso no lo tienes asentado, repásalo antes de entrar en prácticas.

    Resultado esperado al finalizar¶

    Si la unidad está bien aprendida, el alumno no solo “hace un CRUD”, sino que entiende que:

    • la base de datos resuelve la persistencia;
    • PDO reduce el acoplamiento al motor;
    • la seguridad empieza ya en cosas aparentemente pequeñas;
    • una aplicación web profesional necesita estructura, pruebas y criterio técnico.
