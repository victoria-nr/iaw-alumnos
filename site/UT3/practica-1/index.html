    Práctica 1. Agenda básica con SQLite y PDO¶

    1. Título¶

    Agenda básica de contactos con PHP, SQLite y PDO

    2. Sentido de la práctica¶

    Esta práctica sirve para afianzar el patrón completo de acceso a datos con la mínima fricción posible.

    La decisión de usar SQLite aquí es intencionada:

    • elimina la complejidad de administrar un servidor de base de datos separado;
    • permite centrar la atención en PDO;
    • facilita comprender el ciclo CRUD completo antes de pasar a MariaDB/MySQL.

    3. Objetivos¶

    Al finalizar la práctica deberías ser capaz de:

    • conectar PHP con una base de datos SQLite usando PDO;
    • crear la tabla principal desde PHP;
    • realizar altas, consultas, modificaciones y borrados;
    • validar datos en servidor;
    • usar consultas preparadas;
    • mostrar resultados escapando la salida HTML.

    4. Tiempo estimado¶

    4 a 5 horas de trabajo efectivo.

    5. Contexto funcional¶

    Vas a construir una pequeña agenda web para guardar contactos personales o profesionales.

    Cada contacto tendrá, como mínimo:

    • nombre;
    • email;
    • teléfono;
    • fecha de creación.

    6. Estructura sugerida¶

    Puedes reutilizar la estructura de proyecto de la UT2 y ampliarla.

    Estructura sugerida:

    practica-ut3-agenda/
├── config/
│   └── database.php
├── public/
│   ├── index.php
│   ├── crear.php
│   ├── editar.php
│   └── borrar.php
├── data/
│   └── agenda.sqlite
└── README.md

    7. Requisitos obligatorios¶

    7.1. Conexión con SQLite mediante PDO¶

    La aplicación debe disponer de una función o archivo centralizado para la conexión.

    7.2. Creación de tabla desde PHP¶

    Debes crear la tabla contactos desde código PHP, no exclusivamente a mano.

    7.3. Operaciones CRUD completas¶

    La aplicación debe permitir:

    • crear un contacto;
    • listar contactos;
    • editar un contacto;
    • borrar un contacto.

    7.4. Validación en servidor¶

    Como mínimo:

    • nombre obligatorio;
    • email obligatorio y válido;
    • teléfono opcional con longitud razonable.

    7.5. Consultas preparadas¶

    Las operaciones con datos variables deben usar prepare() y execute().

    7.6. Salida escapada¶

    Los datos mostrados en HTML deben imprimirse con htmlspecialchars() o equivalente.

    8. Modelo de datos mínimo¶

    Tabla: contactos

    Campo Tipo orientativo Restricciones
    id INTEGER Clave primaria, autoincremental
    nombre TEXT Obligatorio
    email TEXT Obligatorio
    telefono TEXT Opcional
    created_at TEXT Obligatorio

    9. Fases de trabajo¶

    Fase 1. Preparar el proyecto¶

    1. Crea la estructura de carpetas.
    2. Prepara config/database.php.
    3. Comprueba que PDO SQLite está disponible.
    4. Asegúrate de que la carpeta data/ existe.

    Fase 2. Crear la conexión¶

    Configura una conexión con:

    • PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION
    • PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC

    Fase 3. Crear la tabla¶

    La tabla debe poder crearse desde PHP.
    Puedes hacerlo:

    • en un script de inicialización;
    • o al arrancar la aplicación, de forma controlada.

    Fase 4. Listado principal¶

    En index.php muestra:

    • listado de contactos;
    • botón o enlace a “Nuevo contacto”;
    • acciones de editar y borrar por cada fila.

    Fase 5. Alta de contacto¶

    En crear.php:

    1. muestra formulario;
    2. recoge datos;
    3. valida;
    4. inserta con consulta preparada;
    5. redirige al listado o muestra confirmación.

    Fase 6. Edición¶

    En editar.php:

    1. recibe un id;
    2. carga el registro actual;
    3. muestra formulario precargado;
    4. valida;
    5. ejecuta UPDATE.

    Fase 7. Borrado¶

    En borrar.php:

    1. recibe el id;
    2. ejecuta DELETE por POST;
    3. vuelve al listado.

    10. Evidencias a entregar¶

    Entrega o deja accesible:

    • código fuente completo;
    • captura del listado con varios registros;
    • captura de un alta correcta;
    • captura o breve explicación de una validación fallida;
    • breve fichero README.md indicando:
    • cómo ejecutar el proyecto;
    • dónde se configura la conexión;
    • cómo se crea la tabla y qué campos tiene;
    • qué validaciones has implementado;

    No es necesario entregar una interfaz sofisticada. Lo importante es la lógica y la implantación.

    11. Errores típicos que debes evitar¶

    • usar rutas relativas incorrectas al fichero SQLite;
    • olvidar crear la carpeta data/;
    • mezclar lógica, HTML y SQL sin ningún orden;
    • crear la tabla solo desde Adminer o phpMyAdmin;
    • concatenar datos del formulario dentro del SQL, debes usar prepare() y execute();
    • no validar el email;
    • borrar con GET por simple enlace;
    • mostrar datos sin escapar, debes usar htmlspecialchars() o equivalente al imprimir datos en HTML;
    • no controlar el caso de id inexistente.

    12. Pistas útiles¶

    Pista 1¶

    Haz primero que funcione el listado aunque esté vacío.

    Pista 2¶

    Después implementa el alta.

    Pista 3¶

    Cuando el alta funcione, editar y borrar serán más sencillos de completar.

    Pista 4¶

    No intentes embellecer la interfaz antes de que el flujo CRUD funcione.

    13. Ampliaciones opcionales¶

    Si terminas pronto, añade una o varias de estas mejoras:

    • buscador por nombre;
    • orden por nombre o fecha;
    • mensaje de confirmación tras alta/edición/borrado;
    • campo notas;
    • control para evitar emails duplicados;
    • pequeño diseño con CSS simple.

    14. Qué se está evaluando realmente¶

    Aunque parezca una agenda sencilla, esta práctica permite observar casi todo el RA6:

    • identificación e integración del SGBD;
    • conexión desde PHP;
    • creación de tabla desde código;
    • consulta y actualización de información;
    • seguridad básica;
    • verificación de funcionamiento.

    15. Rúbrica de evaluación de la práctica¶

    Bloque Peso orientativo
    Conexión PDO + SQLite 1,5
    Creación de tabla desde PHP 1,5
    Alta y listado 2,0
    Edición y borrado 2,0
    Validación y seguridad básica 2,0
    Orden, claridad y explicación 1,0
    Total 10,0

    Interpretación rápida¶

    • 9-10: funcional, ordenado y bien explicado.
    • 7-8,9: correcto, con fallos menores.
    • 5-6,9: cumple lo básico pero con debilidades.
    • <5: no demuestra todavía los mínimos de la práctica.

    16. Checklist del alumno antes de entregar¶

    • La conexión funciona.
    • La tabla se crea desde PHP.
    • Puedo insertar un contacto.
    • Puedo listar contactos.
    • Puedo editar un contacto.
    • Puedo borrar un contacto.
    • He validado nombre y email en servidor.
    • He usado consultas preparadas.
    • Escapo la salida al mostrar datos.
    • Sé explicar qué hace PDO y por qué uso SQLite aquí.

    17. Cierre de la práctica¶

    Antes de darla por finalizada, responde en tu README a estas dos preguntas:

    1. ¿Qué ventajas te ha dado SQLite para arrancar esta práctica?
    2. ¿Qué parte crees que cambiaría si migraras la misma app a MariaDB/MySQL?
